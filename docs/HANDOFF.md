# IranLegalHUB — فایل تحویل برای ادامه در چت جدید

> این فایل کل وضعیت پروژه را دارد. در چت جدید این فایل را پیوست یا paste کن، آخرین `IranLegalHUB_updated.zip` و `IranLegal_laws_master_table.xlsx` را هم بده و بنویس «از همین‌جا ادامه بده».
> آخرین به‌روزرسانی: پایان این چت (محیط من بین چت‌ها ریست می‌شود؛ فقط فایل‌های تحویلی می‌مانند و اسکریپت‌های موقت من از بین می‌روند).

---

## ۰. دستور کار پیشنهادی برای چت جدید (به ترتیب اولویت)
1. **آیین دادرسی کیفری** را از صفحه‌ی اختبار از نو بساز (متن فعلی غلط است؛ بند ۳-الف).
2. ۵ قانون «فوری» جدول (بند ۳-ب) را با فایل‌هایی که کاربر می‌فرستد اضافه کن.
3. ۵ قانون ثبتی که از PDF آمده‌اند را با صفحه‌ی اختبار جایگزین کن (بند ۳-ج).
4. مواد کم‌شده را پر کن (بند ۳-د) و نسخه‌های قدیمی را به‌روز کن (بند ۳-ه).
5. تست روی گوشی واقعی را از کاربر بخواه (بند ۳-ز).
6. کاربر گفت بخش آزمون بیش از حد سنگین است و حذفش کرد؛ **دوباره آزمون پیشنهاد نکن** مگر خودش بخواهد.

## ۱. کاربر و قواعد کار (حتماً رعایت کن)
- فارسی بنویس، مختصر و مستقیم؛ جواب کوتاه بده و فقط در صورت لزوم توضیح اضافه کن. وقتی گفت «بدون حرف اضافی» فقط لینک/نتیجه را بده.
- کاربر از گوشی (اپ Claude، مرورگر Chrome اندروید) کار می‌کند و پروژه روی **GitHub Pages** است: `geekneuron.github.io/IranLegalHUB`.
- **مواد منسوخ را حذف نکن**؛ نگه‌دار و داخل پرانتز «(منسوخ)» بنویس (بند ۲-ز). هیچ ماده‌ای را از خودت نساز؛ اگر منبع ماده‌ای نبود، جایش را خالی بگذار و در توضیح قانون بنویس.
- هرچه می‌سازی، با تست jsdom چک کن و **حتماً zip نهایی را تحویل بده** (`present_files`). همه‌چیز را توی `/mnt/user-data/outputs/` بگذار.
- کاربر ترجیح می‌دهد مرحله‌به‌مرحله پیش بروی؛ وقتی چند کار خواست «به ترتیب» انجام بده و بعد از هر مرحله وضعیت بگو.
- قبل از ساخت هر فایل (docx/xlsx/pdf) skill مربوطه را بخوان؛ قبل از خواندن PDFهای آپلودی skill «file-reading» را بخوان.
- اختبار (`ekhtebar.ir`) **fetch خودکار را مسدود کرده** (`ROBOTS_DISALLOWED`)؛ کاربر باید صفحه‌ها را ذخیره (MHTML) و آپلود کند. لینک بدهی، خودش دانلود می‌کند و می‌فرستد. فقط URLهایی را که واقعاً در نتایج جستجو دیدی بده؛ حدس نزن.
- حق نشر: سؤال‌ها و توضیحات پاسخنامه‌ی اختبار را عیناً کپی نکن؛ فقط برای تحلیل مبحث استفاده کن.

## ۲. معماری فنی پروژه

### ۲-الف) ساختار پوشه (`IranLegalHUB_fixed/`)
```
index.html          # همه‌ی تب‌ها: داشبورد، جستجو، فلش‌کارت، آمار پیشرفت، نشان‌شده‌ها، یادداشت‌ها، قوانین، تنظیمات
style.css           # تم روشن/تاریک (کلاس body.dark-theme)، فلش‌کارت، مرور شبانه، آمار، چیپ‌ها
script.js           # همه‌ی منطق (یک closure بزرگ داخل DOMContentLoaded)
data.js             # const lawManifest = { 'tab-...': { title, info, article_word, warning?, suspect?, related?, files:[{title,path}] } }
laws/**.json        # متن قوانین (فرمت بند ۲-ب)
guides/constitution_guide.json
sw.js               # Service Worker (کش آفلاین؛ نسخه‌ی کش: ilh-cache-v11)
manifest.json       # PWA (شورتکات‌ها: فلش‌کارت، مرور شبانه، آمار)
precache-laws.json  # فهرست فایل‌های قانون برای دانلود آفلاین (با tools/build_precache.py ساخته می‌شود)
assets/fonts/Vazirmatn.woff2 + OFL.txt   # فونت محلی + مجوز
assets/icons/*      # آیکون‌های PWA
tools/format_articles.py   # یکدست‌سازی متن مواد (خطوط، تبصره، بندها)
tools/build_precache.py
```

### ۲-ب) فرمت فایل قانون (JSON)
```json
{ "file_title": "...", "article_range": "1 تا N", "note": "مصوب ... ",
  "divisions": [ { "type": "فصل", "title": "فصل اول- ...", "articles": [ { "article_number": 12, "text": "..." } ],
                   "subdivisions": [ ... ] } ] }
```
- هر گره فقط **یکی** از `articles` یا `subdivisions` را نمایش می‌دهد (اگر هر دو بود باید یک بخش «مواد عمومی» بسازی).
- `article_number` می‌تواند عدد صحیح باشد یا رشته: `"54 مکرر"`، `"95 مکرر 1"`، `"واحده"`، `"124 (تکرار)"` (وقتی دو ماده با یک شماره‌اند).
- برچسب نمایشی را `article_word` همان قانون می‌سازد («ماده» یا «اصل» یا «بند» در قانون اصلاح مالیات ۱۳۹۴).
- بعد از ویرایش: `python3 tools/format_articles.py <فایل‌ها>` و `python3 tools/build_precache.py` و بالا بردن شماره‌ی `CACHE_NAME` در `sw.js`.

### ۲-پ) ثبت قانون در `data.js`
هر کلید `tab-xxx` یک قانون است. فیلدها: `title`، `info` (یک جمله)، `article_word`، `warning` (کادر زرد بالای صفحه)، `suspect: true` (قانون مشکوک؛ از فلش‌کارت و مرور شبانه کنار گذاشته می‌شود و در منوی فلش‌کارت نیست)، `related: [{key,label}]` (دکمه‌های «قوانین مرتبط»)، `files: [{title,path}]`.
> `lawManifest` یک `const` است؛ در jsdom با `window.eval("lawManifest")` بخوانش.

### ۲-ت) قراردادهای متنی
- **منسوخ:** `"(منسوخ)\n[به‌موجب ... نسخ صریح شده است.]\nمتن سابق- ..."`؛ منقضی: `"(منقضی‌شده)"`. مواد منسوخ در فلش‌کارت و مرور شبانه نمی‌آیند (`isRepealedText`).
- **نیم‌فاصله:** «می‌شود»، «بانک‌ها»، «ترین/تر»، «به‌طور/به‌منظور/به‌موجب»، «ه‌اند/ه‌ای».
- **اعراب:** فتحه، ضمه، کسره و سکون حذف شده؛ **تنوین و تشدید نگه‌داشته شده**.
- حرف‌های عربی `ي ك` به فارسی `ی ک` تبدیل می‌شوند؛ تطویل `ـ` حذف.
- **درس مهم:** در regexهای فارسی، بازه‌ی `\u0600-\u06FF` ویرگول عربی `،` (U+060C) را هم شامل می‌شود؛ lookahead باید فقط **حروف** را مستثنا کند: `[\u0621-\u063A\u0641-\u064A\u067E\u0686\u0698\u06A9\u06AF\u06CC]`، وگرنه «بانکها،» اصلاح نمی‌شود (یک‌بار ~۱۰۰۰ مورد را از دست داده بودم).
- «ه+ای» در برابر «ها/های»: «سرمایه‌ای» نه «سرمای‌های»؛ با واژه‌نامه‌ی خود قوانین تشخیص بده.

### ۲-ث) قابلیت‌های برنامه (وضعیت فعلی)
- ۶۱ قانون، جستجوی سراسری (بدون انتخاب قانون)، نشان‌شده‌ها (⭐) و یادداشت‌ها، چاپ/PDF با فونت وزیرمتن، تم تاریک، اندازه‌ی متن.
- **فلش‌کارت (جعبه‌ی لایتنر):** `ilh-fc-srs-v1` = `{id: {b: جعبه 0..5, d: زمان مرور بعدی, n: تعداد, l: لغزش}}`، فاصله‌ها `[0,1,3,7,16,35]` روز؛ سه امتیاز دوباره/سخت/بلدم؛ حالت‌ها: مرور امروز، همه، نشان‌شده‌ها، سخت‌ها؛ اندازه‌ی جلسه ۱۰/۲۰/۳۰/همه؛ جهت معکوس (متن←شماره)؛ ☆ نشان‌کردن؛ کشیدن چپ/راست؛ میان‌برها (فاصله، ۱، ۲، ۳، S)؛ پنل «📦 جعبه‌ها»؛ مهاجرت خودکار از کلید قدیمی `ilh_flashcard_known_box_v1` به جعبه‌ی ۴. تنظیمات در `ilh-fc-prefs-v1`.
- **مرور شبانه:** تمام‌صفحه‌ی مشکی/گرم، از نشان‌شده‌ها یا ۱۵ ماده‌ی تصادفی، Wake Lock، تایمر خاموشی ۱۰/۲۰ دقیقه.
- **آمار پیشرفت** (`ilh-stats-v1`): مرور فلش‌کارت، درصد «بلدم»، سررسید، مسلط، روز پیاپی، نمودار ۷ روز، تسلط به تفکیک قانون.
- **PWA:** manifest + آیکون‌ها + SW + دکمه‌ی نصب + «دانلود همه‌ی قوانین» برای آفلاین (پیام‌های `CACHE_ALL` و `CACHE_STATUS` به SW).
- لینک‌های ورودی: `?tab=flashcards&mode=due|all|starred|hard`، `?tab=progress`، `?night=1`.
- **حذف‌شده:** کل بخش آزمون (به درخواست کاربر).

### ۲-ج) محیط و تله‌ها
- محیط من بین چت‌ها ریست می‌شود. اگر `/home/claude/p/...` نبود: zip تحویلی را باز کن.
- MHTMLهای اختبار با `Content-Transfer-Encoding: binary` ذخیره می‌شوند؛ با پارسر ایمیل خراب می‌شوند. HTML را دستی بین `<!DOCTYPE html>` و `------MultipartBoundary` جدا و UTF-8 دیکد کن.
- ساختار مواد در اختبار: «ماده N- متن» یا «ماده N (اصلاحی تاریخ)- متن» یا «ماده N [به موجب … نسخ صریح شده است.]». بندهای شماره‌دار `۱ـ` را به `1- ` تبدیل کن؛ «ماده واحده» جدا پردازش می‌شود.
- در قوانینی که ماده‌ی قبلی را نقل می‌کنند (مثل قانون کاهش حبس تعزیری، ساماندهی مسکن) شماره‌ی ماده‌های نقل‌شده با شماره‌ی خودِ قانون تداخل دارد؛ با «شماره‌ی مورد انتظار پشت‌سرهم» تفکیک کن.
- **PDFهای اختبار:** متن لایه‌ی PDF حروف «لا» را به‌صورت «ال» یا «ل» می‌دهد («اعالم»، «لزم»، «صالحیت»)؛ با واژه‌نامه‌ی ساخته‌شده از خود قوانین پروژه (ZWNJ حذف‌شده) تصحیح کن، سپس کلمات چسبیده («بتصرف» → «به تصرف»، «وزارتدادگستری») را اصلاح کن. در PDFهای قدیمی آزمون وکالت ارقام ۴ و ۶ هر دو `0` خوانده می‌شوند.
- تعداد مواد درست: آیین دادرسی مدنی ۵۲۹، آیین دادرسی کیفری ۶۹۹، قانون تجارت ۶۰۰، مدنی ۱۳۳۵، مجازات اسلامی (کتاب ۱–۴) ۷۲۸.
- کتاب پنجم تعزیرات (۱۳۷۵) شماره‌های ۴۹۸–۷۸۴ دارد و با کتاب چهارم (دیات ۴۴۸–۷۲۸) **عمداً** هم‌پوشانی عددی دارد (دو قانون مختلف).

## ۹. دستورالعمل افزودن/اصلاح یک قانون (قدم‌به‌قدم؛ اسکریپت‌های قبلی من گم شده‌اند)
1. کاربر صفحه‌ی اختبار را ذخیره می‌کند (فایل MHTML بدون پسوند) → HTML را بین `<!DOCTYPE html>` و `------MultipartBoundary` جدا کن و UTF-8 دیکد کن (نه با `email`).
2. محتوا را از `class="entry-content` تا `<!-- .entry-content` بگیر؛ `script/style/svg/ez-toc` را حذف کن؛ سرتیترها `<h1-6>` را علامت بزن؛ بقیه را با `</p|div|li|tr|ul|ol>` و `<br>` به خط تبدیل کن؛ HTML entity را باز کن.
3. خط‌ها را به مواد بشکن: `^ماده\s*(\d+)\s*(مکرر\s*\d*)?\s*(\([^)]*\)\s*)*[\-–—ـ:]+\s*(.*)` (ارقام فارسی را به لاتین ببر). حالت‌ها:
   - `ماده N (اصلاحی ...)–` → عبارت داخل پرانتز را دور بریز؛ `ماده N [به موجب ... نسخ صریح شده است.]` → «(منسوخ)» + مبنا؛ بعدش اگر «متن سابق» آمد زیر همان ماده بگذار.
   - `ماده واحده` و `بند N` (قانون‌های اصلاحی) و `ماده N.` (نقطه به‌جای خط تیره) و `ماده – N` (آیین‌نامه‌ها).
   - مواد نقل‌شده داخل قوانین اصلاحی: فقط وقتی شماره == شماره‌ی مورد انتظار بعدی سربرگ ماده است، وگرنه ادامه‌ی ماده‌ی قبلی.
   - سرتیترهای `باب/فصل/مبحث/بخش` سلسله‌مراتب بساز؛ گرهٔ دارای هم‌زمان مواد و زیرگره را به «مواد عمومی» تبدیل کن.
   - بعد از آخرین ماده، خط‌های «قانون فوق مشتمل بر…»، «تازه‌های قوانین»، «برچسب‌ها»، لینک‌های «اینجا کلیک کنید» را حذف کن.
4. نرمال‌سازی (بند ۲-ت): `ي ك` → `ی ک`، اعراب، نیم‌فاصله، فاصله‌ی بعد از `)`، `۱ـ` → `1- `، «تبصره N-».
5. اگر منبع PDF است: `pdftotext` (حالت ساده برای متن پیوسته؛ `-layout` برای ستون‌بندی) → حذف سرصفحه/شماره‌صفحه → تصحیح «ال/لا» با واژه‌نامه‌ی قوانین پروژه → چسبیده‌ها → سربرگ‌ها با شماره‌ی **پشت‌سرهم** (ماده‌ی `last+1..last+3`).
6. فایل را در `laws/batchN/` بگذار، `tools/format_articles.py` را اجرا کن، در `data.js` ثبت کن (`info`، `related`، در صورت نیاز `warning`)، `tools/build_precache.py`، شماره‌ی `CACHE_NAME` در `sw.js`.
7. تست jsdom: صفحه را باز کن، تعداد قوانین سایدبار (`#sidebar-full-laws-list .sidebar-sublink`) و تعداد `.article` همان قانون را با تعداد مورد انتظار مقایسه کن؛ خطای `window.error` نباشد. (`npm i jsdom` لازم است؛ `fetch` را به `http.server` محلی وصل کن.)
8. zip را بساز (`zip -qr` از پوشه‌ی `IranLegalHUB_fixed`) و `present_files` کن. ردیف قانون را در اکسل «موجود» کن.
